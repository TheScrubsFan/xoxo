# Game Move Validation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Запретить недопустимые ходы на сервере и проверить полную партию двух игроков.

**Architecture:** Контроллер делегирует проверку и запись хода сервису `Games::MakeStep`. Сервис блокирует строку игры в транзакции, читает актуальное состояние, проверяет правила и атомарно сохраняет изменения; контроллер отвечает HTTP и публикует состояние только после успешного завершения сервиса.

**Tech Stack:** Ruby 3.0.1, Rails 6.0, PostgreSQL, Minitest, Action Cable.

**Spec:** `docs/superpowers/specs/2026-11-13-game-move-validation-design.md`

## Global Constraints

- Сохранить успешный HTTP-контракт и формат рассылки существующего Vue-фронта.
- Ошибочный ход возвращает JSON и HTTP 422; никаких изменений состояния и сообщений.
- Не менять алгоритмы победы и ничьей или процесс присоединения игроков.
- Не удалять и не перезаписывать пользовательские изменения; не пушить и не коммитить без отдельного запроса.

## Review Focus

- Отсутствующий, некорректный или чужой `cell.id` не вызывает изменение другой игры и не даёт 500.
- Наблюдатель, игрок до присоединения второго и игрок после окончания игры не могут сделать ход.
- Два конкурентных хода проверяются под блокировкой на свежем состоянии; результат не содержит двойного хода.
- Ошибка сохранения откатывает назначение символа, ход и клетку и не вызывает рассылку.
- Победный ход завершает партию, сохраняет победителя и транслирует актуальное состояние.

### Task 1: Правила и атомарность хода

**Files:**
- Create: `app/services/games/make_step.rb` — валидация и транзакционное выполнение хода.
- Modify: `app/controllers/games_controller.rb` — вызов сервиса, JSON-ошибка и broadcast после успеха.
- Test: `test/controllers/games_controller_test.rb` — HTTP-контракт и побочные эффекты.
- Test: `test/services/games/make_step_test.rb` — транзакционный откат и одновременные запросы.

**Interfaces:**
- Consumes: `Game#current_gamer`, `Games::Logic::Win.perform(game)`, `Games::Logic::Draw.perform(game)` и существующие отношения `game.gamers`, `game.cells`, `game.steps`.
- Produces: `Games::MakeStep.call(game:, user:, cell_id:)` возвращает обновлённый `Game` после успешной транзакции; при нарушении правил возбуждает `Games::MakeStep::InvalidMove` с сообщением для JSON. Непредвиденные ошибки записи не маскируются как ошибка правил.

- [ ] **Step 1:** Добавить запросные тесты: наблюдатель, второй игрок до первого хода, игра с одним игроком, занятая клетка, клетка другой игры, завершённая игра и отсутствующий/некорректный `cell.id`. Для каждого утверждать статус 422, наличие JSON-поля `error`, отсутствие изменения `Game`, `Gamer`, `Cell`, `Step` и отсутствие broadcast; для чужой клетки отдельно проверить отсутствие изменений её игры.
- [ ] **Step 2:** Запустить `DISABLE_SPRING=1 bundle exec rails test test/controllers/games_controller_test.rb` под Ruby 3.0.1; убедиться, что новые тесты обнаруживают отсутствующие проверки, а не ошибку подготовки тестовых данных.
- [ ] **Step 3:** Добавить `Games::MakeStep.call(game:, user:, cell_id:)` и `InvalidMove`: в транзакции получить `game` через `lock!` до чтения правил; проверить состояние, двух игроков, участие, текущего игрока и свободную клетку через `game.cells`; назначить `x` первому и `o` второму игроку, использовать `create!`/`update!`, проверить победу и ничью с прежним порогом и вернуть актуальную игру. Все проверки и записи производить под одной блокировкой.
- [ ] **Step 4:** Передать параметры контроллера в сервис без исключения для отсутствующего `cell`; `InvalidMove` преобразовать в `{ error: message }` и 422; вызвать существующий broadcast только после успешного возврата сервиса, сохранив успешный ответ.
- [ ] **Step 5:** Добавить сервисный тест отката: вызвать реальный сервис на действительном ходе, заставить сохранение клетки выбросить исключение на уровне модели, проверить что состояние, символ и история не изменились. Проверить отсутствие broadcast в соответствующем HTTP-тесте при сбое записи.
- [ ] **Step 6:** Добавить PostgreSQL-тест конкурентности с двумя соединениями и синхронизацией без sleep: два одновременных запроса одного игрока на один и тот же ход, один успех, один `InvalidMove`, одна запись `Step`, одна занятая клетка. Не использовать транзакционные фикстуры для этого теста; гарантировать очистку только созданных тестом записей.
- [ ] **Step 7:** Запустить `DISABLE_SPRING=1 bundle exec rails test test/controllers/games_controller_test.rb test/services/games/make_step_test.rb`; все тесты проходят, включая откат и конкурентность.
