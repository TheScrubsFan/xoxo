# Spec Delta

## Purpose

Сохранить взаимодействие клиента с игрой и текущим пользователем при обновлении окружения приложения.

## ADDED Requirements

### Requirement: Создание игры
Система MUST позволять авторизованному пользователю создавать игру с полем 10 на 10 клеток и возвращать идентификатор игры клиенту.

#### Scenario: Создание игры авторизованным пользователем
- **WHEN** пользователь отправляет POST /games
- **THEN** создаётся игра с 100 клетками, а JSON содержит идентификатор в поле game.id

### Requirement: Получение игры и участие
Система MUST возвращать состояние игры и присоединять к ней первых двух различных пользователей; последующие пользователи остаются наблюдателями.

#### Scenario: Присоединение второго игрока
- **WHEN** второй авторизованный пользователь запрашивает GET /games/:id
- **THEN** ответ содержит актуальное состояние игры с двумя игроками и клиентам рассылается обновлённое состояние

#### Scenario: Повторное посещение и наблюдатель
- **WHEN** существующий игрок повторно открывает игру или третий пользователь запрашивает игру с двумя игроками
- **THEN** дополнительный игрок не создаётся и возвращается состояние игры

### Requirement: Ход и рассылка состояния
Система MUST сохранять допустимый ход игрока и публиковать обновлённое состояние игры подписчикам комнаты игры.

#### Scenario: Ход в свободную клетку
- **WHEN** участник делает допустимый ход через POST /games/:id/make_step с идентификатором клетки
- **THEN** сохраняется ход, клетка получает символ игрока и рассылается обновлённое состояние игры

### Requirement: Завершение игры
Система MUST отражать в состоянии игры победу при пяти подряд и ничью, определяемую игровой логикой.

#### Scenario: Победный ход
- **WHEN** ход формирует пять символов игрока подряд по горизонтали, вертикали или диагонали
- **THEN** игра завершается и состояние содержит победителя

#### Scenario: Ничья
- **WHEN** игровая логика после хода определяет ничью
- **THEN** игра завершается без победителя

### Requirement: Информация о текущем пользователе
Система MUST возвращать данные текущего авторизованного пользователя через GET /users/current.

#### Scenario: Авторизованный запрос
- **WHEN** авторизованный пользователь запрашивает GET /users/current
- **THEN** ответ JSON содержит сведения о нём в поле user

### Requirement: Доступ к игровым HTTP-маршрутам
Система MUST требовать авторизации для игровых маршрутов и получения текущего пользователя.

#### Scenario: Неавторизованный запрос
- **WHEN** неавторизованный пользователь обращается к игровому маршруту или GET /users/current
- **THEN** система требует входа вместо выполнения запрошенного действия
